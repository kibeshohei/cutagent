# PLAN.md 運用手順

`PLAN.md`（リポジトリ直下）は **Claude セッション間の引き継ぎメモ**。
新しいセッションがこれを読むだけで、直前の作業を把握して同じように作業を再開できる状態を保つ。

## 使うタイミング

- **セッション開始時** → まず `PLAN.md` を読み、「現在の状態」と「次にやること」を把握してから動く。
- **作業が一区切りついたら** → コミットする前に `PLAN.md` を更新する。

## PLAN.md の構成

現行の `PLAN.md` を正とする。以下のセクションを維持する。

1. **ヘッダ** — このファイルの役割を説明する注意書き。
2. **`## 現在の状態（YYYY-MM-DD 時点）`**
   - 日付
   - ブランチ名（および直 push 禁止などの注意）
   - 「何がある？」表（場所 × 状態）
   - 「技術的な決定事項（変えないこと）」
3. **`## 次にやること（優先順）`** — `🔲` 付きの番号リスト。各項目に概要を添える。
4. **`## 完了済み`** — `[x]` のチェックリスト。

## 更新ルール

- 「現在の状態」の日付を、その日の日付に更新する。
- タスクが終わったら「次にやること」から消し、「完了済み」へ移す。
- 技術的な決定は **なぜそうしたか（理由）** を必ず残す（例: Huma を v2.31 にした理由 = v2.38 が Go 1.25 必須のため）。
- 簡潔に、スキャンしやすく。新セッションがこれだけ読めば作業を再開できる粒度を保つ。冗長な経緯は書かない。
